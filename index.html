知源 · 跨学科知识同源翻译机

用你已经掌握的知识，去理解一个陌生的领域。

一、评委 3 分钟怎么验

打开线上链接即可，不需要注册、没有登录页（首次访问时前端静默建一个匿名身份）。 建议按下面三条走一遍——每一条都是真调大模型，不是预置动画。

路径 A：跨学科「发现同源」（核心功能，请留 3–6 分钟）

底部导航 求知 → 输入方式选 手动创建 → 粘贴：

人体血糖的负反馈调节：血糖升高时胰岛素分泌增加，促进细胞摄取葡萄糖；血糖降低时胰高血糖素分泌增加，促使肝糖原分解，两者共同把血糖稳定在正常范围。

点「发现同源」。这一步要真调大模型，实测 147 秒（同一个入口另一次实测 325 秒， 耗时随模型负载波动），页面会轮询显示进度，请不要中途刷新。 完成后你会看到：

  • 5 个候选概念，横跨 5 个学科（实测）：生态学「生态系统稳态」、免疫学「免疫负反馈」、 控制工程「PID 控制」、计算机网络「网络流量控制」、经济学「市场均衡」——多数和血糖没有 共同词汇，是被"逻辑结构"匹配上的
  • 每个候选点开有五维逻辑画像、同源度（这次实测 94.7%–99.6%）与术语与机制角色对照
  • 一份跨学科学习报告：共同的机制骨架、成立条件、失效边界、已知差异、推荐学习路径。 报告只把证据够格的候选标为可靠——实测这次只列出「免疫负反馈、网络流量控制」两条， 其余候选照样显示分数，但不展开结论

上面这段输入不在知识库里（库里 11 条没有"血糖"），所以不存在"拿库里的条目去库里查"的 取巧。检索靠的是机制锚点（负反馈 / 调节 / 稳定），不是主题词重合——这正是设计意图： 同一个机制在哪个学科里出现，就该被找出来。而如果输入连一个字面锚点都没有，检索闸门会 返回空列表，页面老实显示「当前证据不足，不强行建立类比」，不硬凑类比。

路径 B：读懂它（约 10–30 秒）

求知 → 手动创建 → 粘贴：

免疫系统的负反馈调节：当病原体被清除后，调节性T细胞会抑制效应T细胞继续增殖，防止免疫反应过度而损伤自身组织。

点「读懂它」，实测约 16 秒：给出核心意思、关键机制与因果拆解（这次抽出的概念是「免疫系统」）， 同时展示五维逻辑画像与关键术语，并可一键存为卡片、进入复习计划。

路径 C：知乎搜索 → 整合为学习笔记

求知 → 知乎搜索 → 输入 负反馈 为什么能让系统稳定。 结果来自知乎开放平台官方搜索接口（不是爬页面正文）——实测返回 3 条真实知乎回答， 第一条是《【控制理论】负反馈的本质：系统如何用误差不断修正自己》。

勾选 2–6 篇 → 「整合为学习笔记」。实测选 3 篇得到一篇约 1000 字的笔记，标题 《负反馈如何实现系统稳定》，结构是「先建立整体理解 → 核心概念与运行机制 → 不同资料补充的观点 → ⋯」，并在文末标注来源条数。系统在所选摘要范围内去重、归纳共同知识、 保留互补与分歧观点，产出后置顶展示，原始文章列表保留在下面供逐条核对， 再进入笔记编辑器继续编辑。

二、这是什么

学新东西时最省力的路，是用已经会的东西去类比。但类比有两个老问题：说不清为什么像， 以及不知道什么时候就不像了。知源把这条路做成一件可以计算、可以追问、可以复习的事。

它处理四个具体问题：

  1. 专业材料读得懂字面，读不懂机制、因果和例子；
  2. 跨学科类比停在"听起来很像"，没有结构依据，也没有失效边界；
  3. 搜到的一堆文章重复、互补、互相矛盾，手工整理成体系化笔记成本很高；
  4. 读过记过，但没进入可持续的复习和自测。

和"又一个 AI 笔记应用"的区别：知源的判定不交给模型。模型负责读懂和讲解， "是否同源"由本地逻辑引擎在固定向量上算出来——同一次输入，判定结果可复现、可解释、 可指出是哪个维度贡献了结论。

三、核心机制

1. 把「像不像」拆成三步，各司其职

文本  →  ① 检索：从策展语料里找出值得比较的候选   （RAG，字面锚点）
      →  ② 画像：把两侧都压成 5 维逻辑向量        （模型抽取，结构固定）
      →  ③ 判定：在向量上算同源度，过阈值才出报告  （本地确定性计算）

关键的分离是 ① 和 ③：检索相关性不等于同源结论。RAG 只回答"哪些候选值得比较"， "是不是同源"由逻辑引擎独立算，报告里的证据可以一路追回语料条目。

2. 五维逻辑画像 + 确定性同源度

五个维度（system_closure / causal_chain_length / negative_feedback_strength / randomness_entropy / zero_sum_resource_level）各归一到 0.0–1.0。

默认用余弦相似度算同源度，也支持 Wasserstein 作为对照方法；默认阈值 0.72， 低于阈值不生成映射报告。模型不能修改或重算这个分数——它只能依据已经算出的分数和 候选材料来写讲解。

为什么强调这点：如果判定也交给模型，同一段输入换个采样就换个结论，报告里的"依据" 就成了事后编的说辞。分开之后，同源度是可复现的，模型的输出则被限定在"讲解与教学"。

3. 报告必须交代边界

一份同源结果不是"相似度 87%"这个数字，而是一份带约束的学习报告，明确列出：

  • 共同的机制骨架（为什么算同源）
  • 成立条件与失效边界（在什么范围内这个类比还成立）
  • 已知差异与禁止外推的结论
  • 一份可靠性评审（可靠 / 有保留地可靠 / 不足以支撑）

这是产品刻意保留的"不好看但要紧"的部分：类比被用错，通常不是因为不像，而是因为 没人说清它从哪一步开始不像。

4. 检索闸门：可解释的字面锚点

候选检索的放行条件是存在可解释的锚点——概念名被原话包含、描述或机制被原话包含、 或抽出的关键词命中（含人工维护的别名组，如「自我纠错 ↔ 负反馈」）。

闸门判的是"有 / 没有"，不比较分数：分数里含"模型这次抽了几个词"这一项， 拿它比阈值会让同一段话有时出候选、有时整片空白。闸门只管放行， 候选之间的排序仍然走原来的加权分数。

四、与知乎生态的契合度

知源把知乎当作知识入口而不是分发渠道——它的每个环节都对着知乎内容的一种特性：

知乎内容的特性 知源里对应的能力
大量专业长文、答主经验，读完要很久 读懂它：先给通俗解释与逻辑画像，再决定要不要深读
同一个话题下多篇回答重复、互补、互相矛盾 多篇整合为学习笔记：在所选摘要范围内去重、归纳共识、保留分歧
内容按话题聚合，跨学科的连接藏在机制里 发现同源：跨出话题边界，按底层结构找对应机制
结论常常绑定具体语境，换了场景就不适用 报告强制交代成立条件与失效边界，不把一篇文章的结论当通用规律
收藏和点赞积累很快，但从不回看 设计上要接个人收藏/点赞 → 卡片与复习（见下方「尚未接通」）

当前已上线、评委可点的知乎能力：

  • 搜索（快速搜索 / 研究模式）走知乎开放平台官方接口，不爬取文章页面； 带请求间隔与进程内缓存以保护额度，接口的限流错误（30001）转成带 Retry-After 的 429，让上层退避重试而不是当作故障。
  • 多篇整合为学习笔记：勾选 2–6 篇，把选中的摘要作为事实边界交给模型—— 摘要之外的内容不作为来源事实，原文列表保留供核对。

尚未接通的一条（如实说明，免得评委点了找不到）：个人收藏/点赞同步。 后端已经有授权链路——GET /api/zhihu/oauth/authorize 与 /api/zhihu/oauth/callback （含 state 校验、按用户隔离保存令牌），前端也有「连接知乎知识库」同意页与确认逻辑； 但这一版前端没有任何按钮会打开那个同意页，而主动拉取用户收藏/点赞的接口也还没实现 （/api/zhihu/library/sync 目前只接收前端传入的条目做分类，不向知乎拉取）。 所以演示时这条路径点不到，我们不计入已完成的功能。

五、技术方案

浏览器 H5（原生 JS，无前端框架）
        │  REST
FastAPI（路由 / Service / 鉴权 / 上传 / 静态托管）
        ├── LangGraph Agent：意图路由 → 特征抽取 → 检索 → 同源计算 → 生成 → 落盘
        ├── 确定性逻辑引擎：五维画像、余弦 / Wasserstein
        ├── 本地策展 RAG 语料（data/corpus，随包分发）
        ├── OCR（RapidOCR）与 PDF 文本层抽取（pypdf）
        └── 按 uid 隔离的文件存储 + 进程内会话

几个不那么常见的选择，以及为什么：

  • 不用前端框架：整个前端是原生 HTML/CSS/JS，由 FastAPI 托管。换来的是一条命令起服务、 没有构建步骤，代价是状态管理得自己写。
  • 发现同源是异步任务：单次要跑完整条 Agent 链（检索 → 画像 → 同源计算 → 逐候选生成报告 → 逐个批判），实测 147 秒与 325 秒两次，远超一般网关超时。后端用后台线程 + 任务状态轮询 （POST /api/discover → GET /api/discover/{request_id}），支持取消与结果 TTL 回收 （LC_DISCOVER_JOB_TTL，默认 900 秒）。
  • 模型输出全程受 Schema 约束：解释、映射、报告、批判、复盘小结都有 Pydantic 契约， 报告要求严格 JSON，避免"看起来像结构化输出"的自由文本。

六、工程质量

  • 测试全部离线：不碰网络、不打真实模型、不需要 .env。见第八节。
  • 容器冒烟：.github/workflows/container-smoke.yml 在 GitHub 的真 Linux 机器上用 仓库根那份 Dockerfile 构建镜像、起容器、跑真实请求——等价于云托管平台的构建步骤， 部署前先看它是不是绿的。
  • 降级是显式的：模型端点不可用时返回 LLM_BACKEND_UNAVAILABLE + 503， 扫描版 PDF（没有文字层）会明确提示读不出内容，而不是把空内容伪装成已读取。 前端在模型后端不可用时不发放任何积分。
  • 数据按 uid 隔离：笔记、卡片、附件、知乎资料各自落在 data/users/<uid>/ 与 uploads/<uid>/；写入使用锁 + 临时文件 + 原子替换。

七、本地跑起来（5 分钟）

1. 拿到代码 —— ⚠️ 目录名必须叫 logic_coloc

本仓库的目录本身就是一个 Python 包（模块之间用相对导入 from . import …）， 所以目录名必须和包名一致。而 GitHub 上的仓库名是 isoLogic， Python 不认识这个名字 —— 直接 clone 会得到一个 isoLogic/，启动时报 ModuleNotFoundError: No module named 'logic_coloc'。

所以克隆时显式指定目标目录名：

git clone https://github.com/Scarlett-yzy/isoLogic.git logic_coloc

已经 clone 过了也不要紧，改个名即可：mv isoLogic logic_coloc （Windows：ren isoLogic logic_coloc）

2. 装依赖

cd logic_coloc
pip install -r requirements.txt

Python 用 3.13（与 Docker 镜像的 python:3.13-slim 一致）。 别降到 3.11：scipy==1.18.0 没有 3.11 能用的包，pip install 会直接失败。 matplotlib（离线出图）和 pytest（测试）故意没列进依赖，需要时自己装。

3. 配 .env

cp .env.example .env      # Windows: copy .env.example .env

然后把 .env 里的 LC_API_KEY 换成一把真实可用的密钥。

不填会怎样？ 服务照样能启动、能匿名使用、能看界面，但所有 AI 功能 （提问解释、跨学科发现、笔记复盘）都会返回 {"code":"LLM_BACKEND_UNAVAILABLE"} + HTTP 503 —— 因为每次都要实时调用大模型。 这是体面的降级，不是崩溃。

.env 已被 .gitignore 排除，永远不要提交它；线上由平台环境变量注入。

LC_BRIDGE 和 LC_API_KEY 是要逐字盯的两个条件 —— feature_extractor.py 判定 该说 OpenAI 方言还是 Anthropic 方言时，要求同时满足：LC_BRIDGE 去掉尾斜杠后以 api.openai-next.com 结尾，且 LC_API_KEY 以 sk- 开头。两个都满足才走 POST {LC_BRIDGE}/v1/chat/completions，否则一律走 POST {LC_BRIDGE}/v1/messages。

判定失败不报错，只会静默换协议，表现为「模型有响应但内容为空」：

  • LC_BRIDGE 加了 /v1、或换成别的域名 → 后缀匹配不上 （尾斜杠本身没关系，代码里有 rstrip("/") 兜着）
  • LC_API_KEY 不以 sk- 开头 → 即使域名写对了也走错协议，这条最容易漏

4. 启动 —— ⚠️ 必须在上一级目录执行

因为该目录是包而不是项目根，运行命令得让父目录进 sys.path：

cd ..                                                        # 回到 logic_coloc 的上一级
PYTHONPATH=. python -m uvicorn logic_coloc.api:app --host 127.0.0.1 --port 8000

Windows PowerShell 下把 PYTHONPATH=. 换成 $env:PYTHONPATH=".";。 浏览器打开 http://127.0.0.1:8000/ 即可。

开发时想要改代码自动重启，加 --reload --reload-dir <仓库的绝对路径>：

python -m uvicorn logic_coloc.api:app --reload --reload-dir /绝对路径/logic_coloc

⚠️ --reload-dir 必须写绝对路径。它相对当前工作目录解析，写成相对的 logic_coloc 时，如果 cwd 已经在仓库里就会指向一个不存在的目录， watchfiles 会静默地什么都不监视 —— 症状是「代码明明改了，接口还是旧行为」。

5. 直接用 —— 全程没有账号界面

打开 http://127.0.0.1:8000/ 就能用，不会让你登录。第一次访问时前端会静默向 POST /api/auth/guest 要一个匿名身份（服务端给你分配一个 uid），笔记、卡片、能量 都照常能用，各人数据互不可见。

身份只存在你自己浏览器的 localStorage 里，所以：

  • 换设备 / 换浏览器 / 清浏览器数据 = 换了一个新身份，看不到之前的笔记；
  • 服务端重新部署（或 LC_SECRET_KEY 变了）会让旧 token 当场作废，用户重新打开网站 会拿到新 uid、看到空书架 —— 盘上的数据还在 data/users/<uid>/ 里，只是不再属于新身份。

这是「点击即用」的刻意取舍，不是 bug。产品上没有任何登录 / 注册 / 绑定入口 （2026-09-13 起）：设置里只有「账户与资料」和「关于知源」两个菜单项。

数据和身份都只存在运行目录的 data/ 与 uploads/ 里，按 uid 分目录隔离。

后端其实保留了完整的注册 / 登录 / 绑定接口（api/auth_store.py），但前端不暴露， 属于备用能力，不用管它。公开部署时匿名记录由 LC_MAX_GUESTS（默认 2000）封顶， 超限淘汰最早的那条。

八、跑测试

cd ..                                        # 同上，必须在包的上一级
python -m pytest logic_coloc/tests/ -q

全部离线：不碰网络、不打真实大模型，也不需要 .env。 注意 CI 里不跑 pytest（只做容器冒烟，见第九节），所以测试要在本机自己跑。

九、部署上线

完整参数清单、验证步骤与排错对照表见 docs/部署指南-CloudBase.md。 交付形态是云托管（容器），不是静态站也不是云函数（会话在进程内存、单个请求要跑 70 秒、 还要写本地文件，三条都排除云函数）。Dockerfile 已就绪，docker build -t logic-coloc . 即可。

上线前请务必确认这四条（漏了任何一条，队友/评委看到的都会是「坏的」）：

事项 不做的后果
1 在平台「环境变量」里配 LC_API_KEY（真实密钥，走私密渠道给，别走 git）
再配一把自己生成的 LC_SECRET_KEY		 所有 AI 功能 503；不配 LC_SECRET_KEY 则每次重新部署都让所有人的身份当场作废
2 实例数固定为 1（最小实例数不要设 0） 会话存在内存里，多实例会让 /api/chat 随机 404
3 挂持久化卷 / CFS 到 /app/logic_coloc/data 与 /app/logic_coloc/uploads 容器重启或重新部署会清空身份记录本身与全部笔记、卡片、附件。本地不会遇到这个问题（磁盘一直在），所以特别容易忽略
4 把请求超时设为 ≥300 秒（配 LC_DISCOVER_TIMEOUT=240，必须小于平台超时） 「发现同源」单次要跑约 70 秒，平台默认超时会在半路掐断，表现为「模型服务异常」

知乎相关能力还需要额外的环境变量（不配则对应入口给出明确提示，不影响其余功能）： ZHIHU_ACCESS_SECRET（开放平台搜索），以及 OAuth 三件套 ZHIHU_OAUTH_CLIENT_ID / ZHIHU_OAUTH_CLIENT_SECRET / ZHIHU_OAUTH_REDIRECT_URI。

不用等云平台：先跑容器冒烟

.github/workflows/container-smoke.yml 会在 GitHub 的真 Linux 机器上用仓库根那份 Dockerfile构建镜像、起容器、跑一遍真实请求 —— 等价于云托管平台的构建步骤，但不用登任何 控制台。工作流配置为在 push 到 main 时自动运行，部署前先看它是不是绿的， 绿了说明云上构建也会成功。

⚠️ 推完别马上看 —— 运行记录的注册会滞后，别把「暂时没看到」当成「失败」。 2026-09-13 实测：一次推送后，半小时内都查不到任何运行，一度以为没触发；它是 在下一次推送时才一起补登记的，最终都是 success。所以刷新没看到就 等几分钟再刷，或直接去 Actions 页面手动 Run workflow 拿一个确定的结果 —— 该工作流带 workflow_dispatch，任何时候都能手动起一次。

失败日志需要登录才能看，所以每个失败点都额外输出一条 ::error:: 注解，而注解是公开可读的：

curl -s -H "Authorization: Bearer <你的 token>" \
  https://api.github.com/repos/Scarlett-yzy/isoLogic/actions/runs/<run-id>/annotations

一定带上 Authorization 头：不带就是匿名额度，每小时只有 60 次且按出口 IP 计， 很容易先被别的排查用光，报 API rate limit exceeded 而不是你想要的结果。

它只回答「镜像能不能构建、服务能不能起来、静态资源和鉴权闸门对不对」—— 不跑 pytest（见第八节），也不验真调大模型（CI 里不配 LC_API_KEY，密钥绝不进仓库）。

十、出问题了先看这里

症状 多半是
ModuleNotFoundError: No module named 'logic_coloc' 目录名不是 logic_coloc（见第七节第 1 步）
打开网站看到一层「无法连接服务器 / 刷新重试」 前端建匿名身份失败了，多半是断网或后端没起来。它不是登录页（产品上没有登录页），先修后端再刷新
匿名身份用着用着数据没了 token 存在浏览器 localStorage，清了浏览器数据 / 换了设备就找不回那个 uid。这是设计取舍，产品上没有找回入口（见第七节第 5 步）
「我的能量 / 笔记」换了台设备看不到 同上：身份只在本机浏览器里，换设备就是一个新身份
启动即崩，报 Form data requires "python-multipart" 依赖没装全：pip install -r requirements.txt 里已有它，别单装 fastapi。它不是可选功能，缺了应用起不来
怎么改代码都没反应 / 接口字段还是旧的 --reload-dir 没写绝对路径而静默失效，或服务是改动之前启动的；直接重启
所有 AI 功能返回 503 LLM_BACKEND_UNAVAILABLE .env 没配或 LC_API_KEY 无效；线上检查平台环境变量
模型有响应但内容是空的 协议判定没通过、静默走了另一边。两个条件要同时满足：LC_BRIDGE 去掉尾斜杠后以 api.openai-next.com 结尾、且 LC_API_KEY 以 sk- 开头（见第七节第 3 步）
跨学科理解「一个候选都没有」 检索闸门要求可解释的字面锚点，这是有意的：证据不足时不硬凑类比。换一段与语料有明确交集的文本再试
知乎搜索报「尚未配置知乎开放平台 Access Secret」 没配 ZHIHU_ACCESS_SECRET（见第九节）
传图片报错「模型服务暂时不可用」 容器缺 OpenCV 的系统库（Dockerfile 已装 libgl1 + glib）；本地则看 pip install -r requirements.txt 是否完整
/api/chat 报 session not found 多实例部署，或用了云函数 —— 实例数必须固定为 1
重新部署后「我的账号不存在了」 没挂持久化卷（见第九节第 3 条）
页面没样式、logo 裂图 前端资源走绝对路径 /static/*，必须由后端托管访问；直接双击打开 index.html 不行
跨学科发现很慢（约 70 秒） 正常。它要跑多次大模型采样并生成学习报告
上传的 PDF 复盘时读不出内容 扫描件（没有文字层）读不了，页面会如实提示；有文字层的 PDF 正常

十一、命令行离线演示（不依赖网络）

在包的上一级目录执行：

python -m logic_coloc.run_demo --pair demo1        # 演示对 demo1 / demo2 / demo3
python -m logic_coloc.run_demo --pair demo2 --png out.png

演示文本与演示对预置在 demo_texts.py，结果走本地缓存 data/demo_cache.json。 缓存只服务 CLI，Web 端每次都实时调用大模型、没有离线兜底。
